# Model Card — RaceIQ Skill-Residual Model

This card documents the regression model behind RaceIQ's **skill score**, the
metric that isolates a driver's raw pace from the conditions (tire, track,
weather) they raced in. Written following the standard model-card format
(Mitchell et al., 2019) used for documenting ML models in production.

## Model details

- **Type**: Ridge regression (L2-regularized linear regression), regularization
  strength chosen by 5-fold cross-validation (`sklearn.linear_model.RidgeCV`).
- **Task**: Predict `lap_time_s` from race conditions; the residual (actual − predicted)
  is interpreted as the pace a driver added or lost independent of those conditions.
- **Inputs**: `tire_age`, `track_temp_c`, one-hot encoded `circuit_type`
  (Street / Technical / High-Speed), one-hot encoded `tire_compound` (Soft / Medium / Hard).
- **Output**: Predicted lap time in seconds; downstream, the per-driver mean residual
  is min-max scaled to a 0–100 "skill score".
- **Why Ridge over plain OLS**: the encoded context features are correlated (e.g.
  certain compounds are more common at certain circuit types), which makes
  unregularized coefficients unstable and prone to overfitting on a relatively
  small per-driver lap count. Ridge shrinks coefficients toward zero, and
  cross-validating the shrinkage strength (`alpha`) avoids hand-picking a value.

## Intended use

- Ranking drivers by pace *after* accounting for the conditions they raced in,
  for a portfolio dashboard / resume project context.
- **Not** intended for real-world betting, team strategy decisions, or any
  use where the underlying data isn't verified, high-quality telemetry.

## Training data

- By default, **synthetic** lap data generated by `data/generate_sample_data.py`
  (8 fictional drivers, 6 fictional circuits, 2 seasons) — built so the dashboard
  runs standalone without needing a live data source or API key.
- `data/fetch_real_data.py` is included as a swap-in path to real lap data
  (same schema) for anyone who wants to point this at actual timing data.
- Because the default data is synthetic, all metrics here demonstrate the
  **method**, not real-world driver rankings.

## Evaluation

- **Train R²**: reported live in the app's "Skill score model" panel (typically
  ~0.85–0.92 on the bundled synthetic dataset) and logged by `src/pipeline.py`
  on every run to `runs/run_log.json`.
- **Cross-validated alpha**: selected from `[0.01, 0.1, 1.0, 5.0, 10.0, 50.0, 100.0]`
  (see `config.yaml`) via 5-fold CV; the chosen value is surfaced in-app, not hidden.
- **Uncertainty**: since this is a small, per-driver dataset, point estimates alone
  can be misleading. Every score gets a 90% confidence interval from 500 bootstrap
  resamples of the underlying laps (`bootstrap_confidence_intervals` in `src/metrics.py`),
  shown as error bars in the app rather than asserting false precision.

## Limitations

- Synthetic data by default — coefficients reflect the generator's assumptions,
  not real motorsport physics.
- Linear model: doesn't capture non-linear interactions between conditions
  (e.g. tire degradation accelerating disproportionately at high temperature).
- Small sample size per driver limits how tight the confidence intervals can get,
  which is exactly why they're reported rather than omitted.
- The residual-based "skill" framing assumes the included features (tire, circuit
  type, temperature) capture the relevant conditions; anything unmodeled (traffic,
  mechanical issues, strategy calls) gets folded into the residual too.
